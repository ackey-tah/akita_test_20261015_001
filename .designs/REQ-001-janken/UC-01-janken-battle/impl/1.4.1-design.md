## 1. 実装方針

### domain（`packages/janken/src/domain/game-session/`）

- **`Round`**（Value Object）
  - 状態は `#playerHand`・`#opponentHand`・`#outcome`。コンストラクタは private
  - `between(playerHand, opponentHand)`: `playerHand.against(opponentHand)` で勝敗を 1 回だけ判定して持つ
  - `isDecided()`: 勝敗の `isDecided()` に委ねる
  - `equals(other)`: 2 つの手と勝敗がすべて等しいか
  - `playerHand()`・`opponentHand()`・`outcome()`: 表示用の getter
- **`GameSession`**（Value Object）
  - 状態は `#record: BattleRecord`・`#lastRound: Round | undefined`。コンストラクタは private
  - `start()`: 空の戦績と、直前の勝負なし
  - `acceptsHand()`: 直前の勝負が無いか、あいこなら true
  - `canRematch()`: 直前の勝負があり、勝敗が決まっていれば true
  - `play(playerHand, opponentHand)`: `acceptsHand()` が偽なら error log を出して `JankenError("hand_not_accepted")` を throw する（UC-01 要件 15 を画面ではなくモデルで守る）。受け付けたら、勝負を作り、その勝敗を戦績に加えた新しい対戦の進行を返す
  - `rematch()`: `canRematch()` が偽なら error log を出して `JankenError("rematch_not_available")` を throw する。受け付けたら、戦績はそのままで直前の勝負を消した新しい対戦の進行を返す
  - `equals(other)`: 戦績が等しく、直前の勝負がどちらも無いか等しいか
  - `record()`・`lastRound()`: 表示用の getter

`rematch` を、手を選べる状態（直前の勝負が無い・あいこ）で拒否するのは、「もう一度勝負する」ボタンが出ていない状態でその操作が届くのは経路の誤りで、黙って受け付けると誤りに気付けないため。

### errors

- `JankenErrorCode` に `hand_not_accepted`・`rematch_not_available` を足す

## 4. テスト計画

観測点は domain の単体テスト。受け入れ基準 ID は置かない（UC-01 要件 8・11・15・16 の検証は 1.6.1 の UI 結合テスト）。

| テスト | `describe` | 確かめること |
| --- | --- | --- |
| `Round.test.ts` | `between` | 2 つの手と、手から判定した勝敗を持つ（勝ち・負け・あいこの代表） |
| | `isDecided` | 勝ち・負けは true、あいこは false |
| | `equals` | 2 つの手が同じなら等しい。プレイヤーの手だけ・相手の手だけ違えば等しくない |
| | `playerHand` `opponentHand` `outcome` | 作ったときの値を返す |
| `GameSession.test.ts` | `start` | 戦績が空で、直前の勝負が無い |
| | `play` | 勝負の勝敗を戦績に加え、直前の勝負にする。あいこの後は続けて手を選べる（戦績にあいこが加わる）。勝敗が決まった後の `play` は `hand_not_accepted` で拒否し、ログを出し、戦績は変わらない。元の対戦の進行は変わらない |
| | `rematch` | 勝敗が決まった後は直前の勝負を消し、戦績は残す。開始直後とあいこの後は `rematch_not_available` で拒否しログを出す |
| | `acceptsHand` | 開始直後・あいこの後は true、勝ち・負けの後は false、もう一度勝負した後は true |
| | `canRematch` | 開始直後・あいこの後は false、勝ち・負けの後は true、もう一度勝負した後は false |
| | `equals` | 同じ操作の並びは等しい。戦績が違う・直前の勝負の有無が違う・直前の勝負が違えば等しくない |
| | `record` `lastRound` | 現在の戦績と直前の勝負を返す |

## 5. リスク・注意点

- 「素早く続けて押す」（UC-01 要件 16）はモデルでは連続した `play` の呼び出しで、各呼び出しが新しい値を返すため取りこぼしは起きない。画面からの連打の保証は 1.6.1 の UI 結合テストで確かめる
