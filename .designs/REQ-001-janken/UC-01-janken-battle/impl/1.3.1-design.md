## 1. 実装方針

### domain（`packages/janken/src/domain/battle-record/`）

- **`Percentage`**（Value Object）
  - 状態は `#roundedValue: number | undefined`（計算できないときは `undefined`）。コンストラクタは private
  - `of(part, total)`: `part` と `total` が 0 以上の整数で、`part <= total` であることを検証する。満たさなければ error log（`part`・`total`）を出して `JankenError("invalid_percentage_count")` を throw する。`total` が 0 なら計算できない割合、それ以外は `Math.round(part * 100 / total)`（小数第 1 位の四捨五入。正の数なので `.5` は切り上がる）
  - `isMeasurable()`: 計算できたか
  - `equals(other)`: 丸めた値どうし（計算できない割合どうしは等しい）
  - `value()`: 丸めた整数を返す。計算できない割合に対しては error log を出して `JankenError("percentage_not_measurable")` を throw する（モデル docs の「計算できない割合に対しては使えない」）。表示側は先に `isMeasurable()` で分ける
- **`BattleRecord`**（Value Object）
  - 状態は `#winCount`・`#loseCount`・`#drawCount`。コンストラクタは private
  - `empty()`: 3 つとも 0 回
  - `add(outcome)`: 勝敗に対応する回数を 1 増やした新しい戦績。勝敗の種類は `outcome.equals(Outcome.win())` などで判定し、`kind()` の実値を比べない（Tell, Don't Ask）
  - `countOf(outcome)`: 勝敗に対応する回数
  - `percentageOf(outcome)`: `Percentage.of(countOf(outcome), 3 つの合計)`
  - `equals(other)`: 3 つの回数がすべて同じか

### errors

- `JankenErrorCode` に `invalid_percentage_count`・`percentage_not_measurable` を足す

## 4. テスト計画

観測点は domain の単体テスト。受け入れ基準 ID は置かない（UC-01 要件 9・10・13 の検証は 1.6.1 の UI 結合テスト）。

| テスト | `describe` | 確かめること |
| --- | --- | --- |
| `Percentage.test.ts` | `of` | 四捨五入の境界: 1/8 = 12.5 → 13、1/3 = 33.33… → 33、2/3 = 66.66… → 67、1/200 = 0.5 → 1、1/201 = 0.497… → 0、0/5 → 0、5/5 → 100。合計 0 は計算できない割合。拒否: 負の値・小数・`part > total` は `invalid_percentage_count` とログ |
| | `isMeasurable` | 合計が正なら true、0 なら false |
| | `equals` | 同じ丸めた値は等しい（1/3 と 2/6）、違う値は等しくない、計算できない割合どうしは等しく、計算できる割合とは等しくない |
| | `value` | 丸めた整数を返す。計算できない割合は `percentage_not_measurable` とログ |
| `BattleRecord.test.ts` | `empty` | 勝ち・負け・あいこが 0 回 |
| | `add` | 勝敗ごとに対応する回数だけが 1 増える。元の戦績は変わらない |
| | `countOf` | 勝敗ごとの回数（複数回 add した後） |
| | `percentageOf` | 分母が 3 つの合計であること（勝ち 1・負け 1・あいこ 1 → 各 33、合計 99 のまま）。空の戦績は計算できない割合 |
| | `equals` | 3 つの回数が同じなら等しい、1 つでも違えば等しくない |

## 5. リスク・注意点

- 浮動小数: `part * 100 / total` の結果がちょうど `.5` になるのは `total` が `200 * part` を割り切るときで、そのとき商は 2 進で正確に表せるので `Math.round` の結果は揺れない

## 修正ループの記録

- 1 周目のレビューで収束（要修正の指摘なし）。minor 2 件を任意で直した
  - `equals` のテストを、比は違うが丸めると同じになる組（1/3 と 33/100）にし、丸めた値で比べていることを確かめる
  - `of` の拒否テストで、ログのレベルが error であることも確かめる
