# ユースケース定義: じゃんけんで対戦する

> 置き場: `.designs/REQ-001-janken/UC-01-janken-battle/usecase.md`
> **観客は業務側です。** 技術仕様（アーキテクチャ・DB 設計・クラス構成）はここに書かず、設計フェーズの成果物に書きます。

## 概要

### 目的

プレイヤーがブラウザでコンピュータとじゃんけんをし、勝敗と戦績を見ながら何度でも遊べるようにする。

### スコープ

| 項目 | 内容 |
| --- | --- |
| 対象ユーザー | ブラウザでページを開いたプレイヤー（1 人） |
| 対象業務 | コンピュータとのじゃんけん 1 勝負と、その繰り返し |
| 対象外 | 対人戦・オンライン対戦、戦績の保存（リロードで消える）、ログイン、効果音・アニメーション演出、多言語対応 |

### 画面

| 画面名 | モック・参照先 | 補足 |
| --- | --- | --- |
| じゃんけん画面 | `mockups/janken.html` | 1 画面。戦績を常に表示し、その下が「手の選択」「あいこ」「結果」の 3 状態で切り替わる |

画面ラフは**簡単なラフに限定**します（ワイヤーフレーム程度）。精緻化は設計フェーズで行います。

## 要件

### 要件 1: 手を選んで勝負する

**ユーザーストーリー:** プレイヤーとして、グー・チョキ・パーのボタンを押してコンピュータと勝負し、勝敗を知りたい。

#### 受け入れ基準

1. ページを開いたとき(WHEN)、(THEN)システムは、グー・チョキ・パーの 3 つのボタンを表示すること(SHALL)
2. プレイヤーが手のボタンを押したとき(WHEN)、(THEN)システムは、相手の手をグー・チョキ・パーから等しい確率でランダムに 1 つ選ぶこと(SHALL)
3. 両者の手が決まったとき(WHEN)、(THEN)システムは、グーはチョキに勝ち、チョキはパーに勝ち、パーはグーに勝ち、同じ手はあいことして勝敗を判定すること(SHALL)
4. 判定が勝ちまたは負けの場合(IF)、(THEN)システムは、プレイヤーの手・相手の手・「勝ち」または「負け」の結果を表示すること(SHALL)
5. 判定が勝ちまたは負けの場合(IF)、(THEN)システムは、手のボタンを非表示にし、「もう一度勝負する」ボタンを表示すること(SHALL)

### 要件 2: あいこで再勝負する

**ユーザーストーリー:** プレイヤーとして、あいこになったらそのまま次の手を出し、勝敗が決まるまで勝負を続けたい。

#### 受け入れ基準

1. 判定があいこの場合(IF)、(THEN)システムは、プレイヤーの手・相手の手・「あいこでしょ！」を表示すること(SHALL)
2. 判定があいこの場合(IF)、(THEN)システムは、手のボタンを表示したままにし、「もう一度勝負する」ボタンを表示しないこと(SHALL)
3. あいこの表示中にプレイヤーが手のボタンを押したとき(WHEN)、(THEN)システムは、要件 1 の 2〜5 と同じく新しい勝負として判定・表示すること(SHALL)

### 要件 3: もう一度勝負する

**ユーザーストーリー:** プレイヤーとして、勝敗が決まった後に何度でも続けて遊びたい。

#### 受け入れ基準

1. プレイヤーが「もう一度勝負する」ボタンを押したとき(WHEN)、(THEN)システムは、前回の手と結果の表示を消し、グー・チョキ・パーの 3 つのボタンを表示すること(SHALL)
2. システムは、勝負の回数に上限を設けないこと(SHALL)

### 要件 4: 戦績を表示する

**ユーザーストーリー:** プレイヤーとして、これまでの勝ち・負け・あいこの回数と割合を見て、遊んだ成果を知りたい。

#### 受け入れ基準

1. じゃんけん画面を表示している間(WHILE)、(THEN)システムは、勝ち・負け・あいこの回数と、それぞれのパーセンテージを表示すること(SHALL)
2. 判定が勝ち・負け・あいこのいずれかに決まったとき(WHEN)、(THEN)システムは、該当する回数を 1 増やし、3 つのパーセンテージを再計算して表示すること(SHALL)
3. パーセンテージの分母は、勝ち・負け・あいこの回数の合計とすること(SHALL)
4. パーセンテージは整数で表示し、小数第 1 位を四捨五入すること(SHALL)
5. ページを開いたとき、または再読み込みしたとき(WHEN)、(THEN)システムは、勝ち・負け・あいこの回数をすべて 0 から始めること(SHALL)

### 要件 5: エラー・境界条件

**ユーザーストーリー:** プレイヤーとして、操作の順序や速さに関係なく、正しい勝敗と戦績を見たい。

#### 受け入れ基準

1. 勝ち・負け・あいこの回数の合計が 0 の場合(IF)、(THEN)システムは、3 つのパーセンテージを「-」と表示すること(SHALL)
2. 勝ちまたは負けの結果を表示している場合(IF)、(THEN)システムは、「もう一度勝負する」ボタンを押すまで新しい勝負を受け付けないこと(SHALL)
3. プレイヤーが手のボタンを素早く連続で押した場合(IF)、(THEN)システムは、1 回押すごとに 1 勝負として判定し、戦績の回数の合計を押した勝負の回数と一致させること(SHALL)

## 非機能要件

| 観点 | 要件 |
| --- | --- |
| 性能 | 手のボタンを押してから結果と戦績が表示されるまで 100ms 以内（対応ブラウザの最新版で計測） |
| 認可・セキュリティ | ログイン無し。誰でも遊べる。ゲーム中にネットワーク通信を行わず、外部へ情報を送信しない |
| データ量 | 永続化するデータは無い。戦績はページを開いている間だけメモリに保持する |
| 可用性 | 静的ファイルだけで動作し、サーバ処理を必要としない（hearing Q8） |
| 監査 | 記録しない |
| 動作環境 | PC とスマートフォンの Chrome・Edge・Safari・Firefox の最新版 |
